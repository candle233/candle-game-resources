# Release Review

Read docs/QUALITY.md and docs/PERMISSIONS.md. Inspect current verification fingerprints, feature-specific tests, actual build and human review evidence. For release require target-device launch, asset/credit audit, save compatibility and release-owner approval. Builds are not publications. Never impersonate a reviewer or silently deploy. State what was actually tested, what remains blocked and where evidence is stored.

Use repository-relative commands from the project root. This skill requires the accompanying project Harness files; it is not a standalone game generator.
