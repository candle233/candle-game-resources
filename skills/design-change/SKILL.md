# Design Change

Read docs/CHANGE_CONTROL.md and the exact supplied source sections. Preserve source terminology and ambiguity. List effects on code/data/save migration/assets/tests, then record an authorized task-local interpretation. Update only current design and affected tasks; do not restore archived mechanics or silently replace the design with genre conventions. Re-approve changed acceptance; invalidate prior verification. Do not demand final answers for unrelated future mechanics.

Use repository-relative commands from the project root. This skill requires the accompanying project Harness files; it is not a standalone game generator.
